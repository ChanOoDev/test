## Story
As a doctor,
I want to see my upcoming appointments,
so that I can prepare for my day.

## Context
Read-only doctor workspace reusing E1-S1 schema and RBAC read-scope.

## Functional Requirements
- Doctor sees own upcoming appointments (today + future), plus own checked-in patients.
- Read-only: no create/reschedule/cancel capability.
- Show patient, time, reason, status.

## Constraints
- Strict read-scope: doctor may only ever read own appointments.

## Technical Impact
- Query endpoint (own-appointments), reusing RBAC.
- React doctor view, distinct from receptionist day view.

## Acceptance Criteria
- [ ] Doctor sees all and only own upcoming appointments.
- [ ] No write actions exposed to doctor.
- [ ] Zero-appointment doctor sees empty state, not error.

## Testing
Unit: read-scope query. Integration: doctor cannot read another's. Frontend: empty state.

## Assumptions (from epic)
- A3 status roles, R2 timezone — see epic body.
