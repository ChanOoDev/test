## Story
As a receptionist,
I want to book a future patient appointment for a doctor,
so that the visit is scheduled without conflicts.

## Context
Foundation vertical slice: schema, migration, RBAC, double-booking guard. Other stories (S2–S5) reuse its schema and RBAC.

## Functional Requirements
- Receptionist/admin create appointment: patient, doctor, date/time, reason, status = `scheduled`.
- Server-side double-booking check: no two appointments for same doctor with overlapping time on the same day → 409.
- Future date/time required; past booking rejected (422).
- Validate patient and doctor exist and are active.

## Constraints
- Authorization: receptionist + admin only (doctor cannot create → 403).
- Concurrency-safe conflict check: DB-level guard/transaction, not app-layer read-then-write.
- Timezone normalized server-side, stored in UTC.

## Technical Impact
- Appointment table/schema + migration.
- POST endpoint + CQRS command + FluentValidation + OpenAPI.
- React form with schema validation and error display.
- Establishes RBAC base reused by all later stories.

## Acceptance Criteria
- [ ] Receptionist creates appointment → 201, returned entity status `scheduled`.
- [ ] Overlapping time for same doctor → 409, no row persisted.
- [ ] Past datetime → 422 with validation message.
- [ ] Unknown/inactive patient or doctor → 422.
- [ ] Doctor role → 403.
- [ ] App-level and concurrent double-create both rejected (unit + integration test).

## Testing
Unit: command validator, conflict rule. Integration: conflict on concurrent create, RBAC 403/ validation 422. Frontend: form submit, error rendering.
