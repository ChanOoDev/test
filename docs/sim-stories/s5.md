## Story
As staff,
I want to move an appointment through check-in and completion,
so that clinic flow is visible and accurate.

## Context
State-machine slice reusing E1-S1 schema and statuses.

## Functional Requirements
- Transitions: `scheduled → checked_in → completed`; `scheduled → cancelled` (also `checked_in → cancelled` per assumption A4).
- Check-in: receptionist/admin. Complete: doctor (own) or admin.
- Invalid transitions rejected (e.g. `completed → checked_in`, `cancelled → completed`) → 422 with machine-readable code.
- Every transition recorded with actor + timestamp (audit trail).

## Constraints
- Authorization: role + (doctor: own only).
- State machine enforced server-side; UI merely offers legal actions.

## Technical Impact
- Status transition command + shared validator; audit table.
- Status change UI in views.

## Acceptance Criteria
- [ ] Valid transitions succeed for permitted roles.
- [ ] `cancelled`/`completed` block all further transitions.
- [ ] Doctor can complete own appointment, cannot complete another's.
- [ ] Illegal transition → 422 with machine-readable code.
- [ ] Every transition recorded with actor + timestamp.

## Testing
Unit: state machine table. Integration: RBAC + audit. Frontend: status controls.

## Assumptions (from epic)
- A3 status roles, A4 checked_in cancellable — see epic body.
